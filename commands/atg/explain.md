# Explain

Answer "what am I about to merge?" in plain language: intent, what changed, concrete
before/after examples, and what to watch for. Not a code review (`pattern-check`), not a
dashboard (`story-view`), not a CI table (`status`). Never runs Gradle, commits, posts to Jira,
or touches PRs. Writes `EXPLAIN.md` into an existing story directory (per
**atg-story-artifacts**); never creates one. Reply in the user's language.

## Usage

```bash
/atg:explain                     # ticket from branch, diff origin/main...HEAD
/atg:explain {TICKET}
/atg:explain {TICKET} --pr {N}   # explain that PR's diff instead
```

## Steps

1. **Resolve ticket and diff.** Ticket per atg-story-artifacts; ask once if none. Default diff:
   `git log --oneline origin/main..HEAD`, `git diff --stat origin/main...HEAD`,
   `git diff origin/main...HEAD`. With `--pr N`: `gh pr view {N} --json number,title,body,baseRefName,headRefName,url`,
   `gh pr diff {N}`, and the commit headlines. Note whether a PR already exists for the branch.
   An empty diff means a story-only brief with examples marked "planned, not yet on this branch".

2. **Load context, best effort.** From the story directory: `{TICKET}-story.md`,
   `implementation-plan.md` (prefer `## As-built` and recorded product decisions), any prior
   `EXPLAIN.md` to overwrite. Also the branch changeset (`.changeset/*.md` excluding README)
   and Jira via the **jira-cli** skill, using comments where they override the description.
   Continue from the diff alone if nothing is available.

3. **Classify the surface** and pick example formats. Use labels and payloads that exist in
   the code, never invented copy.

   | Diff signal | Example type |
   |---|---|
   | `SupportedColumn`, CSV labels, `lotimport` | CSV headers plus 2–3 sample rows |
   | `*Request` / `*Response`, controllers | API JSON before/after |
   | `wavebid-a2o-ui/` | UI flow / copy before/after |
   | `db/changelog` | Schema before/after |
   | Mixed | Lead with the user-facing surface |

4. **Spot intentional behaviour changes**: same-shape inputs with different outcomes (blank
   cell used to clear, now no-ops). Sources: Jira comments, plan decisions, As-built, assertion
   flips in specs. Give them their own subsection. If a product A/B choice is unclear, write
   "unclear from ticket — ask product". Never pick a side.

5. **Emit the brief** (prose per the **unslop** skill) in this fixed shape, PR-walkthrough length, no raw diff, no file list.

   ```markdown
   ## Verdict
   {one sentence}

   ## Why it exists
   {ticket ask, related tickets, gap filled}

   ## Business problem
   {what a user can do now that they could not}

   ## What changed (tech, light)
   | Surface | Change |
   |---------|--------|

   ## What it does NOT do
   - {out of scope / unchanged}

   ## Before → After
   {old shape first, then new with additions called out; 2–3 rows: happy path,
    omit-new-field (backward compatible), one edge}

   ## Behavior matrix
   | Input | Result |
   |-------|--------|
   {blank / omitted / explicit → DB or API outcome; skip if no sparse semantics}

   ## Merge confidence
   - Safe if: …
   - Watch out for: …
   - Intentional behavior change: … (or "none")
   ```

6. **Persist `EXPLAIN.md`** when the story directory exists. Header: `# {TICKET} — Plain-language
   change brief`, generated by, date, branch, diff base, PR URL or `none open`. Then the brief.
   Overwrite, never append. Mention the path in one line. No story directory: chat only, say so
   once.

7. **Close with one situational pointer**: no PR yet → `/atg:story-gap` then `/atg:ship`; PR
   open → `/atg:status` or `/atg:review-feedback {N}`; story artifacts missing → optional
   `/atg:brief`; user only wanted understanding → nothing.

**Next:** situational, per step 7.
